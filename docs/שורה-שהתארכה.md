# שורה שהתארכה (פרומפט 41, 15.11.2026)

בלאוקמי גירסא כל פסקה בוורד היא שורה שבעל הפרויקט כיוון. בהדפסה המוגדלת (גוף 11.5 נק') חלק מהשורות גולשות.
המנגנון מחזיר אותן לשורה אחת, או חותך אותן לשתיים במקום הנכון, בשינוי הקטן ביותר.

## הרכיבים

- **הפרופיל** `tools/print/profiles/a4-large.json` ("A4 מוגדל"): גוף 11.5 נק' (fsFromMeasure 19.103), מרווח 14.21, תוס' 7.85.
  `keepAbsoluteFrom: 10.5872`: משנה, ד"ה משנה, נושא, חציצה, הסבר ואמוראים נשארים בגודלם המוחלט של a4.
  a4 נשאר ברירת המחדל. בחלון ההדפסה, למנהל בלבד: "גודל אות: רגיל / מוגדל" (לשירות ההפקה נשלח בשם הקצר `a4lg`).
- **כלי 1, הצרה** (במנוע, `squeeze25` ב-`tools/print_engine.js`): word-spacing שלילי קודם, אחריו letter-spacing, עד 2.5% מרוחב השורה
  ולא יותר. אם אינו מספיק - לא מצרים כלל. חל בכל פרופיל, ואינו נוגע בטקסט. `render_pdf.py --sq25 0` מבטל, למדידה.
- **המחולל** `tools/overflow/overflow_gen.py`: מריץ את המנוע על מסכת שלמה בשני הפרופילים (`--lines`), ופסקה שיש לה יותר שורות
  ב-a4-large היא "גולשת". לכל אחת: הדף, הטקסט, המילים שגלשו, וכמה חסר (פיקסלים ואותיות ממוצעות). הפלט: `data/overflow/<מסכת>.json`.
- **כלי 2** (בקוד): `tools/overflow/abbr.py` בונה את `data/overflow/abbr.json` מקובצי הוורד - רק צורה שמופיעה אצל בעל הפרויקט 5 פעמים
  ומעלה. בלי שמות ובלי קיצור דו-משמעי. לא נוגע בפסוק במירכאות, בסוגריים ובהפניות.
- **כלים 3-5** (העובד, על המנוי): `data/overflow/sugg/<מסכת>.json`, בצורה `{tool:3, find, replace}` או `{tool:4, split_before, side}`.
  `orig` הוא הנוסח שעליו נכתבה ההצעה: אם הנוסח השתנה - ההצעה אינה מוצגת (נספרת ב-`stale`).
- **הבדיקה**: כל הצעה נמדדת במנוע (אותה הצרה ואותו טיפול במילה בודדת כמו בהדפסה), ב-a4-large וב-a4. הצעה שגולשת - אינה מוצגת.
  לפני כן נבדק שהבדיקה משחזרת את מספר השורות של ההדפסה המלאה בנוסח הנוכחי; אם לא - המחולל עוצר.
- **הממשק** `tools/overflow_ui.js` (בתוך mas.js, אחרי סכם): קו גלי אדום דק והמילים שגלשו באדום (CSS Highlight, בלי לגעת בטקסט),
  לחיצה פותחת חלונית: קבל / ערוך / הצעה אחרת / השאר / בטל, Enter ו-Esc, וכפתור "↵ N" בסרגל (הבאה). לכלי 2 גם "קבל את כל ההצעות
  מהסוג הזה במסכת". "קבל" עובר דרך skmApply של סכם - אותן רשומות של העורך, ומשם לפרסום ולוורד דרך `tools/cloud_word.py` בלבד.
- **למידה**: כל הכרעה נשמרת בשרת (`/bakara/dec`, מסכת `ov-<מסכת>`). `tools/overflow/learn.py` מושך אותן ל-`data/overflow/decisions/`,
  וראשי תיבות שבעל הפרויקט כתב או אישר נכנסים ל-`approved-abbr.json` ומשם לכלי 2.
- **ריצה אוטומטית**: `.github/workflows/overflow.yml` אחרי כל פרסום של השומר, על המסכתות שב-`data/overflow/config.json` (כרגע ברכות).
  שאר המסכתות רק אחרי שבעל הפרויקט יעבור על ברכות.

## בדיקה מהירה

```
PRINT_CHROMIUM=... uv run --with playwright python tools/overflow/mirror_site.py --slug berakhot --out _work/mirror
PRINT_CHROMIUM=... uv run --with playwright python tools/overflow/overflow_gen.py --slug berakhot --site _work/mirror
uv run --with playwright python tools/print/render_pdf.py --site _work/mirror --slug berakhot --all --dev --profile a4-large \
   --ovapply data/overflow/berakhot.json --out x.pdf      # כמה עמודים אחרי ההצעה הראשונה של כל שורה (בזיכרון בלבד)
```

## כותרות ביותר משורה (פרומפט 48, תיקון 4, 17.11.2026)

כותרת (נושא, ד"ה משנה) שתופסת יותר משורה בהדפסה:
א. המנוע מצר אותה עד 2.5% (רווחים ואותיות, בלי לגעת בטקסט). אם אינו מספיק - שובר אחרי " - " או ": " הקרוב לאמצע, ואחרת שורות מאוזנות (לא מילה בודדת בשנייה). הקוד המשותף: headNL ו-headSqueeze ב-print_engine.js.
ב. מה שנשאר ביותר משורה (בגודל כלשהו) נכנס לרשימת "שורה שהתארכה" כפריט כותרת (key = h<מזהה היחידה>, li = 0, head = nose/dh).
ג. הצעות: כלי 2 (ראשי תיבות מן הרשימה, רווחים) וכלי 3 (ניסוח קצר של העובד, בקובץ data/overflow/sugg/<מסכת>.json תחת h<מזהה>). הצעה מוצגת רק אם במנוע, בשני הגדלים, אחרי אותה הצרה, הכותרת נכנסת בשורה אחת. חיתוך ואיחוי אינם חלים על כותרת.
ד. בדף, במצב מנהל: הכותרת מסומנת בקו גלי, ולחיצה פותחת את אותה חלונית (קבל / ערוך / הצעה אחרת / השאר). "קבל" מחליף רק את נוסח השורה [כותרת-נושא:...] דרך skmApply, כמו כל עריכה.
ה. המנוע רושם את הכותרות ב-lines=1 (R.hlines: מספר השורות בפועל, בלי השבירה היזומה), ובדוח headMulti גם את מזהה היחידה.

## הכרעות שנשארות לתמיד (פרומפט 49 חלק 0, 17.11.2026)

הכלל של מיכאל (16.11): שורה שהוא החזיר לשורה אחת (קבל, ערוך, איחוי, חיתוך) נשארת כך לתמיד, בתצוגה, במצב דפוס, בכל הדפסה ובוורד.

א. מה קרה: ב-16.11 בבוקר מיכאל קיבל בברכות שתי הכרעות (ד: חיתוך "שיש בו שתיים...", ח. "בפי ושט"). ב-17:38 ו-17:39 קבלת הצעת "סכם" שנכתבה על הנוסח שלפני ההכרעה החזירה את הנוסח הישן, כעריכה רגילה. הקיפול (21:07) קיפל את מה שהמנהל ראה, ולכן שום שער לא עצר. הקובץ של 21:54 הודפס כך. השבתת הסנכרון ב-21:12 לא איבדה דבר: כל האיחויים (מחיקת שבירה) של ברכות נבדקו מול הספר ומול ה-PDF, ונמצאו שלמים או נשברו שוב ביד מיכאל עצמו.
ב. המרשם: `data/overflow/keep/<מסכת>.json`. כל הכרעה: הדף, הסוג, ונוסח השורות שחייבות להיות כל אחת פסקה אחת ושורה אחת בהדפסה. `keep.py sync` מוסיף את הכרעות "קבל" ו"ערוך" מן השרת (אינו מוחק).
ג. השחזור דרך השכבה, כמו העורך: רשומות `restore` במרשם, נשלחות בפעולה "העלאת עריכות מן המאגר לנקודת הקליטה" עם `keep:<מסכת>` (רק הרשומות האלה, לא כל המאגר). משם `/live` מגיש אותן מיד, והקיפול הלילי מכניס אותן לספר.
ד. הבודק הקבוע: `render_pdf.py` רושם שורות לכל מסכת שיש לה מרשם, ובסוף מריץ `keep.py check`: הכרעה שחסרה או נשברה עוצרת את המסירה (קוד 3, כמו חפיפה). בהדפסה חלקית, שורה מחוץ לטווח אינה תקלה.
ה. בדף, למנהל: אחרי שהעריכות מן השרת הוחלו, אם הכרעה שבמרשם אינה עוד פסקה בדף - הודעה עם הדף והמילים הראשונות (`lkOverflow.keepCheck()`).
ו. עריכה מאוחרת של מיכאל באותה שורה גוברת: אם הוא שינה אותה בכוונה, מעדכנים את המרשם (או מוחקים ממנו את הפריט) - לא מחזירים.

## איחוי אוטומטי - "מה שנכנס נשאר" (פרומפט 53, 17.11.2026)

מיכאל (17.11.2026): "אני לא מעוניין לאשר פיזית איחויים. זה צריך להיות אוטומטית. אם זה נכנס - שיישאר כך."

א. **נעילה**: כל פסקה שבהדפסה (A4 מוגדל, בסיס B5 מוגדל, וגם A4) תופסת שורה אחת נרשמת ב-`data/overflow/keep/<מסכת>.auto.json`, לפי הנוסח עצמו (אותיות וספרות) ולא לפי מקום. `tools/overflow/auto.py lock` מעדכן אחרי כל פרסום. נוסח נעול שאינו עוד בדף = נערך: יוצא מן המרשם (`released`), והנוסח החדש ננעל אם הוא בשורה אחת. עריכה של מיכאל גוברת תמיד, בלי אישור ובלי ניקוי.
ב. **הבודק**: נוסח נעול שקיים ותופס יותר משורה = שבירה. `render_pdf.py` מריץ `auto.py check` בכל הפקה ועוצר (קוד 3), והפעולה `overflow.yml` נכשלת בקול.
ג. **חסימה בדף**: קבלת הצעת "סכם" שנכתבה על נוסח ישן ("החלף בהצעה" כשהקטע נערך מאז, `p.stale`) אינה דורסת שורה נעולה שאינה בנוסח שעליו נכתבה (`skmApply`, sakem_ui.js). זה מה שקרה ב-16.11 (ד:, ח.). הצעה טרייה - עוברת.
ד. **החלה אוטומטית** (`auto.py pick --commit`, ואז `push`): לכל שורה שגלשה ושהייתה שורה אחת ב-A4, הקטן ביותר שמספיק, ורק אם במנוע, בשני הגדלים, היא נכנסת לשורה אחת (כל חלק בחיתוך):
   כלי 2 (ראשי תיבות מן הרשימה - צורה שמיכאל כתב 5 פעמים ומעלה - או רווח מיותר), אחריו כלי 4 (חיתוך אחרי סימן פיסוק הקרוב לאמצע, בלי שינוי מילה; המחולל מציע אותו מעכשיו גם בלי העובד, בלי נקודתיים ולא בתוך ציטוט או סוגריים), ואחריו כלי 3 רק בשינוי מזערי של מילה אחת (לא פסוק, מירכאות, שמות, מספרים והפניות). ניסוח רחב, איחוי (כלי 5), כותרות ופסקאות ארוכות נשארים הצעה בסימון הקיים.
