# שורה שהתארכה (פרומפט 41, 15.11.2026)

בלאוקמי גירסא כל פסקה בוורד היא שורה שבעל הפרויקט כיוון. בהדפסה המוגדלת (גוף 11.5 נק') חלק מהשורות גולשות.
המנגנון מחזיר אותן לשורה אחת, או חותך אותן לשתיים במקום הנכון, בשינוי הקטן ביותר.

## הרכיבים

- **הפרופיל** `tools/print/profiles/a4-large.json` ("A4 מוגדל"): גוף 11.5 נק' (fsFromMeasure 19.103), מרווח 14.21, תוס' 7.85.
  `keepAbsoluteFrom: 10.5872`: משנה, ד"ה משנה, נושא, חציצה, הסבר ואמוראים נשארים בגודלם המוחלט של a4.
  a4 נשאר ברירת המחדל. בחלון ההדפסה, למנהל בלבד: "גודל אות: רגיל / מוגדל" (לשירות ההפקה נשלח בשם הקצר `a4lg`).
- **כלי 1, הצרה** (במנוע, `squeeze25` ב-`tools/print_engine.js`): word-spacing שלילי קודם, אחריו letter-spacing, עד 2.5% מרוחב השורה
  ולא יותר. אם אינו מספיק - לא מצרים כלל. חל בכל פרופיל, ואינו נוגע בטקסט. `render_pdf.py --sq25 0` מבטל, למדידה.
- **המחולל** `tools/overflow/overflow_gen.py`: מריץ את המנוע על מסכת שלמה בשני הפרופילים (`--lines`), ופסקה שיש לה יותר שורות
  ב-a4-large היא "גולשת". לכל אחת: הדף, הטקסט, המילים שגלשו, וכמה חסר (פיקסלים ואותיות ממוצעות). הפלט: `data/overflow/<מסכת>.json`.
- **כלי 2** (בקוד): `tools/overflow/abbr.py` בונה את `data/overflow/abbr.json` מקובצי הוורד - רק צורה שמופיעה אצל בעל הפרויקט 5 פעמים
  ומעלה. בלי שמות ובלי קיצור דו-משמעי. לא נוגע בפסוק במירכאות, בסוגריים ובהפניות.
- **כלים 3-5** (העובד, על המנוי): `data/overflow/sugg/<מסכת>.json`, בצורה `{tool:3, find, replace}` או `{tool:4, split_before, side}`.
  `orig` הוא הנוסח שעליו נכתבה ההצעה: אם הנוסח השתנה - ההצעה אינה מוצגת (נספרת ב-`stale`).
- **הבדיקה**: כל הצעה נמדדת במנוע (אותה הצרה ואותו טיפול במילה בודדת כמו בהדפסה), ב-a4-large וב-a4. הצעה שגולשת - אינה מוצגת.
  לפני כן נבדק שהבדיקה משחזרת את מספר השורות של ההדפסה המלאה בנוסח הנוכחי; אם לא - המחולל עוצר.
- **הממשק** `tools/overflow_ui.js` (בתוך mas.js, אחרי סכם): קו גלי אדום דק והמילים שגלשו באדום (CSS Highlight, בלי לגעת בטקסט),
  לחיצה פותחת חלונית: קבל / ערוך / הצעה אחרת / השאר / בטל, Enter ו-Esc, וכפתור "↵ N" בסרגל (הבאה). לכלי 2 גם "קבל את כל ההצעות
  מהסוג הזה במסכת". "קבל" עובר דרך skmApply של סכם - אותן רשומות של העורך, ומשם לפרסום ולוורד דרך `tools/cloud_word.py` בלבד.
- **למידה**: כל הכרעה נשמרת בשרת (`/bakara/dec`, מסכת `ov-<מסכת>`). `tools/overflow/learn.py` מושך אותן ל-`data/overflow/decisions/`,
  וראשי תיבות שבעל הפרויקט כתב או אישר נכנסים ל-`approved-abbr.json` ומשם לכלי 2.
- **ריצה אוטומטית**: `.github/workflows/overflow.yml` אחרי כל פרסום של השומר, על המסכתות שב-`data/overflow/config.json` (כרגע ברכות).
  שאר המסכתות רק אחרי שבעל הפרויקט יעבור על ברכות.

## בדיקה מהירה

```
PRINT_CHROMIUM=... uv run --with playwright python tools/overflow/mirror_site.py --slug berakhot --out _work/mirror
PRINT_CHROMIUM=... uv run --with playwright python tools/overflow/overflow_gen.py --slug berakhot --site _work/mirror
uv run --with playwright python tools/print/render_pdf.py --site _work/mirror --slug berakhot --all --dev --profile a4-large \
   --ovapply data/overflow/berakhot.json --out x.pdf      # כמה עמודים אחרי ההצעה הראשונה של כל שורה (בזיכרון בלבד)
```
